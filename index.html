Grok Bot 使用指南

先懂原理与能力层 · 再做实操 · 从入门到深入

前言

本指南按逻辑重新组织：先理解 Bot 是什么、能力从哪里来（连接器 / 插件 / Skills），再讲如何自动化（例程）和进阶用法，最后才是可复制测试的案例。

核心四件事不变：先搜索现有 Bot、异步发送、持续等待结果、把验证过的流程写成例程。

核心原理

什么是 Grok Bot

长期存在的智能代理。每个 Bot 有独立记忆、自己的对话，并共享一台属于你的云电脑（浏览器、文件系统、终端）。工作可以在你关闭笔记本后继续。

何时使用

  • 需要重复执行、在你离开后仍要运行
  • 需要记住长期偏好或项目状态
  • 涉及你的文件、已登录浏览器或已连接服务
  • 跨多个工具的工作流

一次性问答直接对话即可。

记忆机制

每个 Bot 有独立长期记忆。明确要求记住的事实、关键决定会保留。敏感凭证不要放进记忆，走官方连接器。事实变化时主动更新。

连接器、插件与 Skills

三者关系

  • 连接器 / 插件：让 Bot 登录并直接操作外部服务（Gmail、日历、GitHub、Notion 等）。在侧边栏「Connect apps」里添加，一次登录后账号内所有 Bot 可用。优先使用连接器，比纯浏览器点击更可靠。
  • Skills：可复用的「怎么做」。包含使用时机、输入、步骤、校验方式、输出格式、审批边界。通过对话保存，或用「Teach a task」演示生成草稿后再完善。可用 / 引用。
  • 例程（Routine）：决定「什么时候做」。把已验证的 Skill 或流程绑定到时间或事件上。

正确顺序：先用连接器拿到数据 → 把流程做成可靠的 Skill → 再挂到例程上。

Teach a Task

在支持的环境里，让 Bot 观察你完成一次浏览器流程（最长约 10 分钟），自动生成 Skill 草稿。之后需要补充决策规则、失败处理和审批边界，并在安全输入上测试，才能放心使用。

不要在演示中暴露密码；凭证应通过安全方式交接。

实用建议

  • 能用连接器就不要只靠浏览器点击。
  • Skill 要写清楚「何时使用、需要什么、如何验证、什么必须审批」。
  • 在对话里用 / 调用 Skill，用 @ 提到 Bot、例程或连接器。
  • 没有插件的服务仍可通过共享电脑的浏览器操作（需你登录一次）。

例程机制

例程 = 一个 Bot 拥有 + 触发条件（时间或事件）+ 要执行的流程。

好的例程提示要自包含：数据来源、处理逻辑、输出格式、无数据时怎么办、哪些动作必须停下来等人确认。

限制参考：单个 Bot 最多约 50 个例程；计划间隔至少 5 分钟；保留最近约 20 条运行记录；删除后不可恢复。隐藏 Bot 不会停止它的例程。

正确交互流程

  1. 先搜索现有 Bot，避免重复创建
  2. 异步发送任务并持续等待最终结果
  3. 把成功流程明确保存为 Skill
  4. 需要自动化时再创建例程，并写清触发与边界
  5. 多个 Bot 可能承担同一持续职责时，先问你选择

进阶机制

四要素框架

Context（你是谁与约束） · Connections（工具访问） · Capabilities（Skills） · Cadence（例程节奏）。缺一不可。

审批与成本

发送、支付、删除、发布、改生产前必须停下来确认。高频例程会快速消耗用量。定期审计：哪些例程还在产生价值、哪些记忆需要更新。

社区案例研究

案例 A：一人公司 8 Agent + 11 Routine

先建 Chief of Staff，再按角色（CMO、CFO 等）逐步添加专家 Bot，每个重复任务单独绑定例程。

案例 B：产品经理 Swarm

研究、策略、营销等 7 个 Bot + 共享协作 Skill。研究 Bot 的每周例程有「无变化则停止」的退出条件。

案例 C：Chief of Staff 作为唯一入口

日常只和总控对话，描述里写明「先检查专家再决定自己做还是转交」。每周短回顾审计学习与纠正。

案例 D：Outer / Inner Loop

Outer 只做调研并产出自包含任务说明；Inner 只执行，减少上下文污染。

案例 E：真实生活系统

礼物预算、行程、保养记录、发票草稿、周末推荐等，每个领域一个 Bot，写操作留审批，从小事开始验证。

实操案例

以下可直接复制测试。建议按顺序做。

案例 1：创建并测试记忆

第一步： 
请创建一个新的 Bot，名称叫「测试助手」，描述是「用于练习记忆功能的 Bot」。
第二步： 
请让「测试助手」记住：我的测试关键词是「香港公司」，以后只要提到这个词就提醒我它记住了。

案例 2：设置简单例程

试试这个： 
请让「测试助手」保存一个例程：每天早上 8 点，检查是否有新消息，如果没有就回复「今日无新消息」。把这个例程保存下来。

案例 3：搜索现有 Bot 并分配

试试这个： 
请搜索现有的 Bot，看看有没有适合做「每日摘要」的。如果有，告诉我候选；如果没有，再建议是否需要新建。

案例 4：电脑操作任务

安全测试： 
请让拥有电脑的 Bot 列出我下载文件夹里最近 5 个文件的名称（如果有的话）。不要修改任何文件。

案例 5：修改与停止例程

试试这个： 
请让「测试助手」把之前的每日例程改成「每天晚上 9 点执行」，并确认已更新。

案例 6：服务集成

试试这个： 
请搜索是否已有邮件相关 Bot。如果有，让它生成今天未读邮件的简短摘要（最多 5 封）。如果没有连接，请告诉我需要授权什么。

信息来源与社区经验

平台内部机制 + 官方文档（docs.x.ai/grok-bot）+ 社区实践（Sawyer Merritt 教程、@bot 团队 tips、solopreneur / Product Compass / Chief of Staff 模式等）。

高频技巧：一个 Bot 一个清晰岗位、总控协调、例程不要过频、Teach a Task 后完善 Skill、重要写操作留审批、定期审计。

总结

先建立能力层（连接器 + Skills），再自动化（例程），用案例验证。遇到具体问题把回复贴回来即可继续调整。
